# COMMON SURFACE — 브랜드 원장 (Brand Source of Truth)

> **문서 ID:** `brand.common-surface.source-of-truth`
> **버전:** `0.1.0-synthetic-brief`
> **상태:** 가상 상업 시나리오용 동결 초안
> **적용 범위:** 제품, 웹, 매장, 패키지, 머천다이즈, OOH, 디지털 광고, 콘텐츠, UX
> **권한 한계:** 아래 제품·성분·효능·가격·시장·권리 정보는 모두 가상 작업값이다. 실제 판매·안전·규제·임상·재고·제조 사실로 사용할 수 없다.

이 문서는 COMMON SURFACE를 그럴듯한 시각 스타일이 아니라 **일관된 브랜드 세계**로 구현하기 위한 정본이다. 디자인팩은 이 원장의 의미를 표현하고, UX Preset은 이 원장의 행동 원칙을 실행한다. 원장에 없는 사실을 이미지·카피·컴포넌트가 임의로 보충하지 않는다.

## 1. 브랜드 한 문장

**COMMON SURFACE는 서로 다른 피부와 서로 다른 하루를 위한, 과장 없는 관리 도구를 만든다.**

### 1.1 핵심 명제

> `CARE IS A COMMON SURFACE.`

관리는 결점을 고치는 의식이 아니라, 몸과 환경과 시간의 상태를 읽고 필요한 순서를 선택하는 일이다. 브랜드는 완벽한 피부를 약속하지 않고, 사용자가 자신의 리듬에 맞는 관리 방식을 발견하도록 돕는다.

### 1.2 브랜드 역할

| 구분 | 정본 정의 |
| --- | --- |
| 우리가 하는 일 | 얼굴·몸·휴대·공간을 잇는 관리 도구와 사용 순서를 설계한다 |
| 우리가 하지 않는 일 | 질환 진단, 치료, 과장된 개선 약속, 성별별 피부 처방, 공포 기반 판매 |
| 고객이 얻는 것 | 이해하기 쉬운 선택, 확인 가능한 상태, 반복 가능한 루틴, 오래 쓰는 물건 |
| 고객이 느껴야 하는 것 | 차분함, 통제감, 신뢰, 자기 방식으로 조정할 여지 |

## 2. 포지셔닝과 차별화

### 2.1 포지셔닝 문장

> **COMMON SURFACE는 남녀 구분과 과장된 효능 경쟁에서 벗어나, 피부 관리의 순서·도구·환경을 하나의 시스템으로 설계하는 유니섹스 케어 브랜드다.**

### 2.2 경쟁 구도에서의 위치

| 시장의 흔한 방식 | COMMON SURFACE의 선택 |
| --- | --- |
| 완벽한 피부의 전후 비교 | 실제 생활의 다양한 상태와 관리 맥락 |
| 성별·연령별 고정된 처방 | 피부 상태·환경·사용 목적 중심의 탐색 |
| 효능을 크게 외치는 광고 | 확인 가능한 정보와 절제된 언어 |
| 제품 하나의 영웅 서사 | 순서와 조합을 이해하는 시스템 |
| 일회성 캠페인 이미지 | 제품·공간·웨어러블 오브젝트가 연결된 세계 |

### 2.3 차별화 증거(가상 시나리오)

1. 제품명을 효능명이 아니라 사용 역할과 동작에서 출발시킨다.
2. 용기·라벨·매장 집기를 같은 모듈 규칙으로 설계한다.
3. 제품 상태와 근거 수준을 고객에게 숨기지 않는다.
4. 스킨케어와 바디·휴대·공간 오브젝트를 하나의 루틴 맵으로 연결한다.
5. 모든 캠페인은 `누구에게 무엇을 언제 왜 보여주는가`를 먼저 정의한다.

## 3. 고객과 사용 맥락

### 3.1 우선 고객군

| 고객군 | 상황 | 기대 | 피해야 할 표현 |
| --- | --- | --- | --- |
| 도시 생활자 | 출근·운동·이동이 반복됨 | 짧고 명확한 루틴, 휴대성 | “바쁜 사람을 위한 기적” |
| 감각 민감 사용자 | 향·질감·포장에 신중함 | 재질·사용감·정보의 투명성 | “모두에게 자극 없음” |
| 루틴 입문자 | 제품이 많아 무엇부터 쓸지 모름 | 단계와 선택 이유 | “이것만 쓰면 충분” |
| 경험 많은 사용자 | 기존 루틴을 조합하고 싶음 | 성분·형태·사용 순서 비교 | 근거 없는 전문가 권위 |
| 선물 구매자 | 상대의 성별·피부를 모름 | 안전한 탐색, 취향 기반 선택 | 성별 고정 패키지 |

### 3.2 사용자의 핵심 질문

모든 접점은 다음 질문 중 하나를 명확히 답해야 한다.

- 지금 이 제품은 어떤 순서와 상황에 쓰는가?
- 이 제품의 사실과 아직 확인되지 않은 정보는 무엇인가?
- 내 선택을 바꾸거나 보류해야 할 이유가 있는가?
- 제품이 없거나 상태가 바뀌었을 때 다음 행동은 무엇인가?

## 4. 제품 세계

제품명은 **가상 working name**이며 효능·임상·규제 문구가 아니다. 제품 상세, 패키지, 광고, UX는 아래 역할과 사용 장면을 기반으로 작성한다.

| ID | 제품 / 형태 | 제품 역할(가상) | 사용 장면 | 연결 오브젝트·콘텐츠 |
| --- | --- | --- | --- | --- |
| `CS-01` | `RINSE` 젤 클렌저 / 펌프 | 씻어내는 첫 단계 | 아침·운동 후·외출 귀가 | 세면대, 물, 30초 루틴 카드 |
| `CS-02` | `BALANCE` 에센스 / 유리 보틀 | 물기 뒤 다음 단계 | 세안 직후, 건조한 실내 | 레이어링 도식, 투명 재질 |
| `CS-03` | `BARRIER` 세럼 / 드로퍼 | 집중 관리 단계 | 환경 변화·건조함을 느낀 날 | HOLD/01 검증 시나리오의 영향 제품 |
| `CS-04` | `SEAL` 데일리 크림 / 알루미늄 자 | 마무리 보습 단계 | 외출 전·취침 전 | 하루의 앞·뒤를 잇는 타임라인 |
| `CS-05` | `SHIELD` 선스틱 / 사각 스틱 | 야외 휴대 단계 | 이동·야외 활동 | 가방 속 오브젝트, 그늘과 빛 |
| `CS-06` | `FIELD` 바디 워시 / 리필 펌프 | 몸을 씻는 단계 | 샤워, 여행, 체육관 | 리필 스테이션, 욕실 선반 |
| `CS-07` | `REPAIR` 핸드 밤 / 튜브 | 손 관리 단계 | 키보드·운전·작업 후 | 작업대, 손의 동작, 패브릭 |
| `CS-08` | `CARRY` 립 밤 / 스틱 | 휴대 보조 단계 | 주머니·파우치·비행 | 티셔츠 포켓, 이동 체크리스트 |
| `CS-09` | `LENGTH` 바디 로션 / 펌프 | 몸의 넓은 면 관리 | 샤워 후·취침 전 | 넓은 면적의 그리드, 침실 |
| `CS-10` | `RESET` 스칼프 린스 / 노즐 | 두피 세정 보조 단계 | 운동 후·주말 리셋 | 물줄기, 수건, 리셋 루틴 |
| `CS-11` | `DRY` 데오도란트 / 롤온 | 데일리 바디 케어 단계 | 출근·운동·이동 | 락커, 티셔츠, 반복 사용 |
| `OBJ-06` | `AIR` 미스트 오브젝트 / 유리·금속 | 공간의 분위기 전환 오브젝트 | 책상·침대 옆·매장 | 공간 그래픽, 조명, 향의 서사 |

### 4.1 제품 상세에 반드시 채울 필드

실제 상업 콘텐츠를 만들기 전 아래 필드를 제품별로 채우고 권한을 부여한다. 값이 없으면 `unresolved`로 표시한다.

```text
product_id / working_name / form / net_amount / price / currency
ingredient_list / usage / frequency / skin_or_body_context
substantiated_claims / prohibited_claims / warning / compatibility
market / channel / stock_state / batch_policy / manufacturer
asset_ids / packaging_revision / rights_status / last_verified_at
```

### 4.2 제품 카피 규칙

- `BARRIER`, `REPAIR`, `SHIELD` 같은 이름은 작업 역할만 전달한다. 치료·회복·차단 효능으로 확장하지 않는다.
- “개선”, “치료”, “완벽”, “무자극”, “임상 입증”은 권한·근거가 등록된 경우에만 사용한다.
- 성별 대신 사용 상황, 질감 선호, 시간, 휴대성, 루틴 단계로 탐색한다.
- 제품 설명은 `무엇인지 → 언제 쓰는지 → 무엇이 확인되지 않았는지 → 다음 행동` 순서로 쓴다.

## 5. 브랜드 경험 원칙

### 5.1 네 가지 경험 원칙

1. **설명 우선** — 먼저 사실과 사용 맥락을 알려주고 설득은 그 뒤에 둔다.
2. **불확실성 가시화** — 확인되지 않은 정보는 빈칸이 아니라 상태로 표시한다.
3. **조용한 통제** — 사용자가 선택·변경·취소·재시도를 이해하고 직접 조작할 수 있게 한다.
4. **회복도 관리다** — 오류·보류·재고 없음에서도 입력과 존엄을 보존하고 다음 경로를 제시한다.

### 5.2 금지되는 경험

- 피부 결점을 확대하거나 불안·수치심을 자극하는 전후 이미지
- 근거 없는 긴급성, 한정 수량, 전문가 권위 연출
- 제품 상태를 색상 하나 또는 아이콘 하나로만 전달
- 사용자의 피부 상태를 진단하거나 자동으로 안전하다고 판정
- HOLD·오류 상태를 브랜드 리뉴얼처럼 감추거나 시각적 장식으로 소비

## 6. 언어와 콘텐츠 시스템

### 6.1 보이스

| 속성 | 해야 할 말 | 하지 말아야 할 말 |
| --- | --- | --- |
| 차분함 | “확인되지 않은 정보는 아직 판단하지 않습니다.” | “걱정할 필요 없습니다.” |
| 정확함 | “이 제품은 로컬 실험 후보입니다.” | “안전한 제품입니다.” |
| 동료성 | “다른 제품을 선택할 수 있습니다.” | “당신에게 꼭 필요한 제품입니다.” |
| 간결함 | “순서 02 / 다음 단계” | 장식적인 형용사 나열 |

### 6.2 콘텐츠 블록

```text

headline / support_copy / usage_context / claim_state
cta / fallback / disclaimer / medium / locale / revision
asset_ids / rights_status / approver / last_verified_at
```

### 6.3 캠페인 3종

| 캠페인 | 목적 | 대표 메시지 | 주요 매체 |
| --- | --- | --- | --- |
| `COMMON ROUTINE` | 브랜드와 제품 순서 소개 | “하루에 맞는 순서를 고르세요.” | 웹, 매장, 패키지 insert |
| `FIELD NOTES` | 실제 생활 장면과 오브젝트 확장 | “관리의 표면은 욕실 밖에도 있다.” | 인물 사진, OOH, 머천다이즈 |
| `HOLD / 01` | 근거·상태·복구 행동 검증 | “확인 중인 것은 확인 중이라고 말한다.” | 웹, 광고 중지/교체, 직원 안내 |

## 7. 시각·에셋 방향

### 7.1 디자인팩 연결

| 계층 | 정본 | 원장 적용 |

| UX Preset | `decision.reserve@0.1.0` | 선택·draft·commit·confirmed·recovery 상태 |

### 7.2 이미지 아트 디렉션

- 사람: 성별·피부색·연령·장애·체형을 넓게 구성하고, 피부를 수정해 결점 없는 표면으로 만들지 않는다.
- 제품: 흰 배경 제품 컷, 사용 중 손 컷, 욕실·락커·책상 환경 컷을 모두 확보한다.
- 공간: 광택보다 금속·유리·종이·천의 실제 질감을 보여준다.
- 구도: 중심 영웅샷만 반복하지 말고 `전체 장면 / 중간 행동 / 디테일 / 사용 후 상태`를 세트로 제작한다.
- 생성 이미지: 합성임을 내부 레지스트리에 기록하고 실제 모델·제품·매장·생산 증거로 표현하지 않는다.

## 8. UX 브랜드 철학

COMMON SURFACE의 UX는 “추천을 많이 하는 인터페이스”가 아니라 **사용자가 자신의 관리 순서를 이해하고 통제하는 인터페이스**다.

### 8.1 행동 원칙

| 원칙 | 구현 기준 |
| --- | --- |
| 선택은 사용자 소유 | 시스템 추천, 사용자의 draft, 확정 결과를 분리 |
| 상태는 사실에 묶임 | 제품·batch·claim 상태는 Product Binding만 참조 |
| 보류도 유효한 결과 | 차단 이유, 영향 범위, 다른 선택, 재시도 경로 제공 |
| 맥락을 잃지 않음 | 필터·입력·선택을 reload/Back 후 복원 |
| 접근 가능한 정보 | 색상 외 텍스트·구조·focus·키보드 경로 제공 |
| 상업 경계 명확화 | 가격·재고·주문·안전 판정은 실제 시스템 연결 전 주장 금지 |

### 8.2 핵심 웹 흐름

```text
제품 탐색 → 제품 역할·상태 확인 → 사용자 draft 선택
→ batch/근거 확인(필요 시) → 명시적 로컬 저장
→ 결과 확인 → 변경·초기화·도움말 또는 대체 경로
```

각 단계에서 `loading`, `invalid`, `blocked`, `unknown`, `confirmed` 상태를 설계하고, 실패해도 입력과 설명을 보존한다.

## 9. 채널 운영 규칙

| 채널 | 고객 과업 | 브랜드가 증명할 것 | 금지 |
| --- | --- | --- | --- |
| 웹사이트 | 탐색·비교·루틴 시작 | 제품 역할, 상태, 다음 행동 | 실제 결제·재고를 가상 데이터로 표시 |
| 오프라인 매장 | 만져보기·상담·구매 검토 | 재질, 순서, 직원 안내 | 진단·치료 상담 |
| 패키지 | 사용·보관·식별 | 제품 ID, 사용법, batch/권리 상태 | 읽을 수 없는 과장 문구 |
| 티셔츠·굿즈 | 브랜드 기억·소속감 | wordmark, symbol, product code | 제품 효능을 패션 문구로 확대 |
| OOH | 짧은 인지 | 명제와 한 가지 행동 | 작은 disclaimers에 의존 |
| 디지털 광고 | 관심→정확한 destination | 캠페인 상태와 landing parity | 랜딩과 다른 claim |
| 지원 접점 | 불확실성 해소 | 기록된 상태와 다음 절차 | 실제 고객센터인 척하는 합성 채널 |

## 10. 권리·규제·생산 필드

상업 배포 전 아래 항목이 모두 `verified`가 아니면 해당 콘텐츠는 실험·검토 상태로만 표시한다.

```text
trademark / domain / font / model-release / image-license
product-formulation / INCI / safety-review / claim-substantiation
manufacturer / packaging-spec / barcode / market-labeling
price / tax / stock / fulfillment / return-policy / support-channel
vendor-proof / color-proof / print-proof / accessibility-review
```

## 11. 변경·승인·버전 관리

### 11.1 변경 요청 단위

변경은 `brand_change_id`를 만들고 다음 순서로 처리한다.

```text
요청 → 영향 제품·캠페인·매체 식별 → 카피/에셋/UX 변경
→ 권한·claim·권리 검토 → 7매체 투영 → 회귀 검사
→ 승인·배포 → rollback record
```

### 11.2 승인 역할

| 역할 | 승인 범위 |
| --- | --- |
| Brand owner | 포지셔닝, 명제, 보이스, 캠페인 방향 |
| Product owner | 제품 역할, 카탈로그, 가격·채널 입력 |
| Regulatory / legal | claim, 라벨, 안전, 권리 |
| Design system owner | Pack·토큰·컴포넌트·반응형 규칙 |
| UX owner | 선택·검증·commit·recovery 흐름 |
| Production owner | 인쇄·원단·매장·광고 vendor proof |

### 11.3 버전 규칙

- 브랜드 명제·포지셔닝 변경은 major revision이다.
- 제품 역할·카피·에셋 변경은 영향 범위를 기록한 minor revision이다.
- 오탈자·링크 수정만 patch revision으로 허용한다.
- R3의 synthetic 값을 실제 승인값으로 소급 변경하지 않는다.

## 12. 완성도 판정표

| 영역 | 완료 조건 |
| --- | --- |
| 브랜드 전략 | 포지셔닝, 고객, 차별점, 금지 경험이 승인됨 |
| 제품 | 12개 stable ID에 역할·사용 장면·권한 필드가 채워짐 |
| 콘텐츠 | 캠페인·카피·disclaimer·fallback이 구조화됨 |
| 에셋 | 매체별 최소 세트, hash, 권리, crop, 상태가 등록됨 |
| UX | 탐색·선택·검증·확정·보류·복구가 동일 의미로 작동함 |
| 생산 | 인쇄·공간·광고·웹의 실제 proof가 있음 |
| 상업 | 가격·재고·결제·배송·반품·지원이 실제 시스템과 연결됨 |
| 검증 | 정적·상호작용·접근성·대표 사용자·외부 권한 증거가 분리됨 |

현재 COMMON SURFACE R3는 앞의 다섯 영역을 **가상 실험 수준**으로 채웠고, 생산·상업·외부 검증은 미해결이다. 이 한계를 숨기지 않는 것이 원장의 일부다.

## 13. 미결정 질문

1. 실제 출시 시장과 우선 판매 채널은 어디인가?
2. 각 제품의 formulation, 용량, 가격, 제조사는 무엇인가?
3. 어떤 claim을 어떤 증거 수준으로 허용할 것인가?
4. 브랜드가 실제로 보유한 모델·제품·폰트·공간·상표 권리는 무엇인가?
5. 매장 직원과 고객지원팀이 사용할 실제 escalation 절차는 무엇인가?
6. 상업 웹사이트에서 실제 결제·재고·배송 시스템과 어떤 방식으로 연결할 것인가?

이 질문이 답변되기 전까지 디자인 결과물은 `synthetic commercial scenario`로 표기하며, 실제 제품 출시물·안전 안내·광고 승인물로 재사용하지 않는다.

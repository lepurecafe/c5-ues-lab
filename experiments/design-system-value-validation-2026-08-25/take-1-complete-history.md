# Take 01 실험 보고서 — COMMON SURFACE

> **문서 유형:** Take 01 종합 실험 보고서
> **보고서 상태:** R4 1차 내부 평가까지 반영 · 외부 평가 대기
> **기간:** 2026-08-25–2026-08-26
> **범위:** COMMON SURFACE 스킨케어·오브젝트 브랜드의 디자인팩 적용, 유지관리, 변경 전파, 최소 브랜딩 검증
> **병렬 비교:** Take 2 랜덤 음악 앱 프로젝션 파이프라인
> **핵심 질문:** Markdown 중심 디자인 시스템이 브랜드를 일관되게 표현하고, 변경·확장·검증까지 감당할 수 있는가?

이 보고서는 최초의 대규모 실험부터 R4 최소 브랜딩 실험까지를 하나의 평가 기록으로 정리한다. 각 점수는 당시의 평가 기준과 증거 수준을 함께 읽어야 하며, 높은 자체 평가가 실제 상업 출시 준비도를 의미하지 않는다. 본 보고서의 최종 결론은 연대기 마지막의 종합 판정과 다음 실험 권고를 따른다.

## 보고서 요약

Take 01은 COMMON SURFACE 브랜드를 통해 Markdown 중심 디자인 시스템의 시각 재사용성, 유지관리성, 변경 전파, 최소 브랜딩 입력의 효과를 단계적으로 시험했다. 초기에는 브랜드 맥락보다 산출물 규모를 먼저 키워 원인과 결과를 분리하지 못했으며, R3에서 운영 복잡성과 증거 관리 결함이 드러났다. R4에서는 실험 규모를 최소화해 고객 상황을 구체화하는 단일 변경이 내부 평가를 `6.2 → 8.1`로 높이는 초기 증거를 확보했다.

**종합 판정:** 시각·운영 시스템의 재사용 가능성은 확인했지만, 상업 브랜드 시스템의 최종 유효성은 아직 검증 중이다. 다음 단계는 R4 외부 블라인드 반복이며, 그 전에는 전체 결과 요약 인덱스를 실제 실행 기록과 동기화해야 한다.

## 1. 처음 세운 실험 구조

처음에는 하나의 실험에서 두 가지를 동시에 확인하려 했다.

```text
Track 1: 가상 브랜드 유지관리
  Design Pack → 브랜드 기준선 → 업데이트 → 7개 매체 전파·회귀

Track 2: 랜덤 음악 앱 제작 파이프라인
  질답 → Flowchart → Low-fi → High-fi
```

공통으로 사용한 것은 UES, Design Pack Library, UX Preset Registry, 평가 프레임뿐이었다. Product Binding과 Brand Application은 트랙별로 독립시킨다는 원칙을 세웠다.

초기 잠정 목표는 다음과 같았다.

- 브랜드 불변조건 보존율 95% 이상
- 매체 전파율 90% 이상
- 단계 간 의미 보존율 90% 이상
- P0/P1 결함 0건
- Stage Score 80점 이상

문제는 이 목표를 세우면서도 **브랜드 자체의 맥락을 먼저 충분히 정의하지 않았다는 점**이다. 브랜드 철학, 고객, 제품 의미, 캠페인 목적, 실제 사용 장면이 얕은 상태에서 매체와 에셋의 규모부터 키웠다.

## 2. R1 — 첫 브랜드 기준선

### 2.1 설정

- 브랜드: `COMMON SURFACE`
- 분야: 성별 구분 없이 사용하는 스킨케어·오브젝트 브랜드
- Design Pack: `pack:industrial-swiss@1.0.0`
- UX Preset: `decision.reserve@0.1.0`
- 핵심 문장: `피부를 위한 일상의 순서.`
- 제품: `CS-01–CS-04` 4종
- 주요 접점: 웹, 패키지, 매장, 티셔츠·머천다이즈, OOH, 디지털 광고, 무드보드

### 2.2 만든 것

- 브랜드명, 워드마크, 축약 마크
- 12열 그리드, 토큰, 한국어 조판 규칙
- 제품 카탈로그와 패키지 전·후면 구조
- 매장·선반·테스터·티셔츠 시스템
- OOH·디지털 광고 3규격
- 웹 제품 선택과 Reserve 상태
- 제품·매장·캠페인·머천다이즈 생성 에셋

### 2.3 당시 평가

R1 자체 평가는 **8.2/10**이었다.

- 브랜드 전략·아이덴티티: 8.4
- 제품·패키지: 8.4
- 매체·에셋: 8.3
- 상업 경계·사실성: 8.5
- 웹 UX: 7.8

하지만 이후 사용자가 지적한 문제는 명확했다.

- 브랜드 이름과 로고의 기억성이 약함
- 제품군과 인물 에셋이 부족함
- 매체별 분위기가 반복됨
- 제품·마케팅 맥락이 충분하지 않음
- 실제 상업 사용을 위한 권리·성분·가격·제조 정보는 비어 있음

R1은 **브랜드 기준선의 첫 형태**로는 의미가 있었지만, 브랜드 자체를 충분히 검증한 결과는 아니었다.

## 3. R2 — 시각 확장과 에셋 증설

### 3.1 목표

R1의 약점을 시각적으로 보강했다.

- 로고를 맞물린 `C/S` 심벌로 재설계
- 제품을 `CS-01–CS-11`과 `OBJ-06`으로 확장
- 인물 장면 8개 추가
- 로고 응용 에셋 4개 매체군 추가
- 얼굴·바디·휴대·오브젝트 제품군으로 분화
- 제품·인물·공간·머천다이즈의 장면 변주 확대

### 3.2 만든 것

R2에는 신규·개선 에셋 **25개**가 추가됐다.

- 제품 11종 + 오브젝트 1종
- 인물 장면 8종
- 심벌·워드마크·가로형 락업 SVG
- 배송·의류·매장·인쇄물 로고 응용
- 확장된 제품 카탈로그·웹 필터·매체 프리뷰

### 3.3 평가와 문제

R2 자체 평가는 **9.1/10**이었다. 그러나 엄격한 관점에서 R1을 다시 평가하면 **7.2/10**이 더 타당하다고 기록했다.

R2가 개선한 점:

- 로고 독자성·이름 기억성
- 인물의 다양성과 장면 폭
- 제품군의 폭과 제품별 식별성
- 로고 응용력
- 페이지 리듬과 시각적 변주

R2가 해결하지 못한 점:

- 풍부한 제품 정보 없이 제품 수만 늘어남
- 브랜드의 고객·구매 동기·캠페인 목적이 여전히 추상적임
- 에셋의 다양성이 브랜드 전략보다 앞섬
- 높은 점수가 자체 평가에 의존함

즉, R2는 **브랜드 맥락의 빈칸을 더 많은 이미지와 제품으로 메우려 한 단계**였다.

## 4. R3 — 유지관리와 통제된 변경 스트레스 테스트

### 4.1 실험 설계

R3는 시각 결과보다 시스템 운영성을 검증하려 했다.

- R3-A: R2 기준선 정상화
- R3-B: `HOLD / 01` 변경을 7개 매체에 전파
- 영향 매체: 무드보드, 패키지, 매장, 머천다이즈, OOH, 디지털 광고, 웹
- 검사: 7개 매체 × 5개 = 35개 체크
- 운영 상태: affected, unaffected, unknown, released, rollback
- 제품 상태: `CS-03`과 합성 batch `CS03-SYN-2608-H01`
- 고객 표면: 내부 운영 프리뷰와 고객용 웹사이트 샘플

### 4.2 발생한 문제

R3 초기 버전은 다음을 드러냈다.

- exact batch 변경이 제품 전체 HOLD처럼 처리됨
- baseline과 HOLD의 접근성 상태가 완전히 분리되지 않음
- release/rollback이 하나의 Binding보다 로컬 boolean에 의존함
- 같은 revision 안에서 의미가 바뀌는 수정이 누적됨
- 매체·에셋·평가 분모가 최신 구현과 완전히 동기화되지 않음

### 4.3 평가 변화

초기 `0.1.1-experiment`는 독립 검토에서 P0/P1 결함으로 **STOP**이었다.

이후 `0.2.0-experiment`에서 다음을 수정했다.

- complete release authority
- 양방향 Product Binding write/readback
- `H01 released`와 `U01 unaffected` 분리
- async settlement 재검증
- batch-aware commit record
- Back/reload retention
- HOLD 재적용과 write-failure guard

최종 독립 평가:

- R3-A: **63/100**
- R3-B: **63/100**
- P0/P1: **0/0**
- hard gate: PASS
- 최종 판정: **REVISE · 조건부 유효**

R3는 운영 시스템의 구조적 결함을 찾는 데는 성공했지만, 브랜드 설득력이나 제품 세계의 완성도를 검증한 실험은 아니었다. 규모가 너무 커서 시스템의 가능성보다 예외·증거·권한 관리의 복잡성이 전면에 나타났다.

## 5. 브랜드 원장 도입

R3까지의 결과를 검토하면서 문제의 핵심이 드러났다.

> 디자인팩은 시각 표현을 잘 통제했지만, 브랜드가 무엇을 말하고 누구에게 어떤 제품을 어떤 맥락에서 제공하는지에 대한 정본이 약했다.

그래서 다음 문서를 만들었다.

[브랜드 원장](r3/contracts/brand-source-of-truth.md)

브랜드 원장은 다음을 정본화한다.

- 브랜드 포지셔닝과 핵심 명제
- 고객군과 사용 상황
- 12개 제품의 역할·형태·사용 장면
- 제품 정보와 claim 권한 경계
- 캠페인 3종과 채널별 목적
- 보이스·금지 표현·UX 철학
- 인물·제품·공간 에셋 방향
- 매체별 최소 에셋 세트
- 변경·승인·버전 관리

이 문서가 이전 R1~R3에 처음부터 있었다면, 디자인과 UX가 빈 공간을 임의의 언어로 채우는 일이 줄었을 것이다.

## 6. R4 — 최소 브랜딩 검증

### 6.1 목적

R4에서는 규모를 의도적으로 줄였다.

- 고객 1명
- 제품 1개: `CS-04 / SEAL`
- 캠페인 1개: `COMMON-ROUTINE-01`
- 접점 5개
- 변경 변수 1개

고정한 것:

- Industrial Swiss Design Pack
- Reserve UX Preset
- 로고
- 제품 이미지
- 토큰·레이아웃·CTA

변경한 것:

- 고객 상황을 일반적인 `하루의 마지막`에서 구체적인 `운동 후 샤워`로 변경

### 6.2 결과

[R4 전후 비교 프리뷰](r4/preview.html)

내부 1차 평가:

- 기준선 평균: **6.2점**
- 개선본 평균: **8.1점**
- 상승 폭: **+1.9점**

특히 상승한 항목:

- 브랜드 식별성: 6 → 8

이번 결과는 제품 이미지나 디자인팩을 바꾸지 않고도, **고객 상황을 구체화하는 것만으로 브랜드·제품·행동의 연결이 개선될 수 있음**을 보여주는 초기 증거다.

다만 내부 평가이고, 외부 블라인드 평가·대표 사용자·실제 상업 시스템 검증은 아직 없다.

## 7. 병렬 Take 2와의 비교

Take 2는 랜덤 음악 앱을 Flowchart → Low-fi → High-fi로 투영한 별도 실험이다. 처음에는 질답이 완료되기 전까지 Flowchart를 만들지 않는 context gate를 설정했다.

질답 이후 `Battle Beat Randomizer`라는 제품 맥락이 확정됐다.

- 사용자: 참가자, DJ, 현장 운영자
- 상황: 랩배틀·댄스배틀에서 비트를 빠르게 확보
- 핵심 상태: 추천, 재생 시도, Playing, 실패, 복구
- 제품 변경: Fair Round Lock
- 모든 음악·아티스트·커버는 synthetic fixture

결과:

- Flowchart: 90
- Low-fi: 92
- High-fi: 94
- Artifact Quality: 92.4/100
- 시스템 유효성: 8.6/10

Take 2가 더 설득력 있었던 이유는 제품과 사용 상황을 먼저 정리했기 때문이다. 그러나 Design Pack strict 적용 50%, UX Preset strict semantic 50%, 공식 재사용률·수정시간 미측정이라는 한계가 남았다.

Take 2는 **맥락을 먼저 정리하면 단계 간 설계 품질이 높아진다**는 비교 사례지만, 지속 가능한 도구 가치까지 최종 증명한 것은 아니다.

## 8. 전체 비교 분석

### 8.1 실험 규모

```text
R1  기준선 만들기
R2  제품·에셋·매체 확장
R3  다중 매체 운영·상태 스트레스 테스트
R4  하나의 브랜드 변화만 검증
```

R1→R3로 갈수록 산출물은 많아졌지만, 브랜드 입력의 구체성은 그 속도를 따라가지 못했다. R4에서 규모를 줄이자 비로소 원인과 결과를 비교할 수 있었다.

### 8.2 독립변수 통제

| 단계 | 동시에 바뀐 것 | 해석 가능성 |
| --- | --- | --- |
| R1 | 브랜드·제품·매체·에셋 | 낮음 |
| R2 | 로고·제품 수·인물·응용 에셋 | 낮음 |
| R3 | 상태 모델·Binding·7매체·rollback | 운영 결함 진단에는 높음, 브랜드 평가에는 낮음 |
| Take 2 | 제품 맥락 후 CR-01 변경 | 중간~높음 |
| R4 | 고객 상황 한 가지 | 가장 높음 |

### 8.3 증거 수준

| 단계 | 주요 증거 | 신뢰도 |
| --- | --- | --- |
| R1 | 정본 MD, 로컬 렌더, 자체 평가 | C1 수준 |
| R2 | 확장 에셋, 반응형·정적 검증, 자체 평가 | C1 수준 |
| R3 | 독립 검토, 상호작용, 정적 validator, E3 local prototype | C2에 가까우나 revision chronology gap 존재 |
| Take 2 | 단계별 캡처, 상태 모델, 독립 QA, E2 | C2 |
| R4 | 브라우저 데스크톱·모바일, 동일 조건 전후 프리뷰 | 내부 1차, C1 |

### 8.4 무엇이 실제로 확인됐나

확인된 것:

- 디자인팩이 토큰·그리드·컴포넌트·시각 언어를 반복시키는 능력
- 상태와 변경을 문서·화면·에셋에 연결하는 가능성
- 제품 맥락이 구체화될수록 브랜드 결과가 설득력 있어지는 경향
- 하나의 Product Binding에서 Flowchart→Low-fi→High-fi 의미를 보존할 가능성

아직 확인되지 않은 것:

- 실제 상업 브랜드로서의 시장 매력
- 실제 제품 효능·안전·가격·재고·제조
- 실제 사진·모델·폰트·상표 권리
- 대표 사용자에게 브랜드가 기억되는지
- 디자인 시스템이 기존 방식보다 실제로 빠르고 저렴한지
- 두 개 이상의 독립 브랜드에서 같은 품질로 재사용되는지

## 9. 가장 큰 교훈

### 교훈 1 — 문제는 야심 자체보다 순서였다

큰 실험을 하는 것이 잘못은 아니다. 다만 다음 순서가 뒤집혀 있었다.

```text
잘못된 순서:
매체·에셋 확장 → 브랜드 의미 추정 → UX와 카피 보충

권장 순서:
브랜드 원장 → 대표 제품·고객·캠페인 → 최소 접점 → 단일 변경 → 확장
```

### 교훈 2 — 에셋은 맥락을 대체할 수 없다

이미지 수를 늘리면 시각적 밀도는 높아지지만, 고객이 왜 이 제품을 보아야 하는지까지 설명해주지는 않는다. 에셋은 먼저 역할과 사용 장면이 정의되어야 한다.

### 교훈 3 — 높은 자체 점수는 시스템 증거가 아니다

R2 자체 평가는 9.1이었지만 R3 독립 평가에서는 63/100이었다. 점수 차이는 결과가 갑자기 나빠졌기 때문이 아니라, 평가 대상이 시각 완성도에서 운영·증거·권한 무결성으로 확장됐기 때문이다.

### 교훈 4 — 최소 실험이 확장 실험보다 더 많은 것을 알려준다

R4는 5개 접점만으로도 브랜드 맥락의 구체화가 결과에 미치는 영향을 관찰할 수 있었다. 이 작은 실험을 통과한 뒤에야 7매체와 여러 제품으로 확장하는 것이 타당하다.

## 10. 현재 상태

- R1: 역사적 기준선
- R2: 시각 확장 기준선

### 문서 관리상의 남은 문제

루트의 `results/results-summary.md`와 Track 2 결과지에는 아직 `not started` 또는 `blocked` 상태가 남아 있지만, Take 2에는 이미 최종 결과가 기록되어 있다. 다음 단계 전에 결과 요약 인덱스를 실제 실행 기록과 동기화해야 한다.

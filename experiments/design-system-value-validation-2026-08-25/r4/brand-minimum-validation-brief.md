# R4 — 최소 브랜딩 검증 브리프

> **문서 ID:** `brief.common-surface.brand-minimum-r4`
> **버전:** `0.1.0-freeze-candidate`
> **목적:** 최소한의 브랜드 입력만으로 브랜딩이 식별·표현·개선되는지 검증한다.
> **상태:** 실행 전 동결 후보
> **범위:** 하나의 고객, 하나의 제품, 하나의 캠페인, 다섯 개의 접점
> **권한 한계:** 모든 제품·효능·가격·권리 값은 가상 실험값이다. 실제 상업 승인이나 안전 근거가 아니다.

## 1. 실험 질문

1. 최소한의 브랜드 정보만으로도 결과물에서 같은 브랜드를 알아볼 수 있는가?
2. 브랜드와 제품의 관계가 장식이 아니라 메시지와 행동으로 표현되는가?
3. 브랜드 입력 한 가지를 개선했을 때 동일한 시스템 안에서 결과가 실제로 좋아지는가?
4. 개선이 특정 화면 하나가 아니라 다섯 접점 전체에 일관되게 전파되는가?

## 2. 고정 조건

| 항목 | 고정값 |
| --- | --- |
| Design Pack | `pack:industrial-swiss@1.0.0` |
| UX Preset | `decision.reserve@0.1.0` |
| Brand Experience | `brand-experience.common-surface@0.1.0-experiment` |
| 제품·상태 데이터 | `binding.common-surface.catalog.r3@0.2.0-experiment`에서 읽기 전용 참조 |
| 고객군 | 성별 구분 없이 도시에서 일하고 이동하는 25–40세 사용자 |
| 상황 | 하루가 길어져 저녁에 간단한 관리 순서를 다시 시작하려는 순간 |
| 대표 제품 | `CS-04 SEAL / 데일리 크림` |
| 캠페인 목적 | 제품 탐색과 첫 루틴 시작 |
| CTA | `루틴 시작하기` |

R4에서 바꾸는 것은 브랜드 입력과 그에 따른 콘텐츠뿐이다. Pack, Preset, 컴포넌트 구조, 평가 항목, 산출물 수는 변경하지 않는다.

## 3. 브랜드 최소 입력

### 3.1 브랜드 핵심

- **약속:** 서로 다른 하루에 맞는 관리의 순서를 쉽게 고르게 한다.
- **가치:** 차분함, 정확함, 자기 조정.
- **남겨야 할 인상:** 과장하지 않지만 기억에 남음, 기능적이지만 차갑지 않음, 누구나 들어올 수 있음.
- **피해야 할 인상:** 병원 같은 불안, 성별 고정, 완벽한 피부 강박, 근거 없는 전문가 권위.

### 3.2 고객 맥락

- 퇴근·운동·이동이 끝난 뒤 복잡한 루틴을 줄이고 싶다.
- 제품이 무엇을 하는지보다 **언제 어떤 순서로 쓰는지**를 먼저 알고 싶다.
- 피부를 진단받거나 평가받는 느낌 없이 자신의 선택을 조정하고 싶다.

### 3.3 대표 제품 카드

| 필드 | 값 |
| --- | --- |
| ID / 이름 | `CS-04 / SEAL` |
| 형태 | 알루미늄 자형 용기, 합성 working form |
| 역할 | 루틴의 마지막에 바르는 데일리 크림 |
| 사용 장면 | 세안·에센스 뒤, 외출 전 또는 취침 전 |
| 감각 단서 | 손바닥에 덜어 넓게 펴 바르는 동작, 무광 금속과 종이 라벨 |
| 확인되지 않은 정보 | 성분, 용량, 가격, 실제 효능, 안전성, 시장 판매 여부 |
| 허용 표현 | `마지막 단계`, `데일리 크림`, `루틴을 닫는 순서` |
| 금지 표현 | `치료`, `장벽 회복`, `무자극`, `임상 입증`, `완벽한 피부` |

## 4. 캠페인 입력

| 항목 | 동결값 |
| --- | --- |
| 캠페인 ID | `COMMON-ROUTINE-01` |
| 핵심 문장 | `하루의 마지막에, 순서를 닫습니다.` |
| 보조 문장 | `SEAL은 관리의 마지막 단계를 위한 합성 제품 후보입니다.` |
| 행동 | 제품 역할을 확인하고 로컬 루틴을 시작한다 |
| 증거 경계 | 실제 판매·재고·가격·효능·안전 판단은 제공하지 않음 |

## 5. 보이스와 카피 규칙

### 해야 할 것

- 짧은 문장과 구체적인 동작을 사용한다.
- 제품의 역할, 순서, 사용 장면을 먼저 말한다.
- 모르는 정보는 `확인되지 않음`으로 표시한다.
- 사용자가 선택·변경·보류할 수 있음을 명시한다.

### 하지 말아야 할 것

- 제품명을 효능이나 의학적 결과로 확장하지 않는다.
- “당신에게 꼭 필요하다”, “지금 당장”, “전문가 추천”을 쓰지 않는다.
- 성별·피부색·나이로 제품을 자동 추천하지 않는다.
- 비어 있는 정보를 분위기용 문장으로 채우지 않는다.

## 6. 최소 산출물 세트

동일한 입력으로 다음 다섯 접점을 만든다.

1. 브랜드 로고 lockup + 핵심 명제
2. 제품 상세 카드
3. 웹사이트 hero와 제품 시작 CTA
4. 패키지 전면 라벨 및 insert 한 장
5. 1:1 디지털 광고와 랜딩 연결

각 산출물은 다음 구조 데이터를 공유한다.

```text
brand_id / product_id / campaign_id / headline / support_copy
usage_context / claim_state / cta / disclaimer / asset_ids / revision
```

## 7. 1차·2차 변경 실험

### Baseline

위 최소 입력을 그대로 사용해 다섯 접점을 만든다. 디자인 문법과 레이아웃은 동일하게 유지한다.

### 단일 개선 변경

다음 중 **한 가지**만 선택해 변경한다.

- 고객 상황을 `저녁의 긴 하루`에서 `운동 후 샤워`로 구체화
- 핵심 문장을 제품 역할 중심으로 더 명확하게 수정
- 제품 사용 동작 사진 세트를 추가
- 로고 lockup의 이름·기호 관계를 개선

선택한 변경 외의 제품 정보, Pack token, UX state, CTA, 평가 분모는 고정한다.

## 8. 평가표

각 항목을 1–10점으로 평가하고 Baseline과 개선본을 나란히 기록한다.

| 평가 항목 | 질문 |
| --- | --- |
| 브랜드 식별성 | 로고나 이름이 없어도 같은 브랜드의 결과물로 보이는가? |
| 차별성 | 다른 스킨케어 브랜드와 구별되는가? |
| 메시지 명확성 | 무엇을, 언제, 왜 쓰는지 즉시 이해되는가? |
| 제품 연결성 | 제품의 역할이 브랜드 철학과 연결되는가? |
| 접점 일관성 | 다섯 매체가 같은 세계를 유지하는가? |
| 에셋 적합성 | 이미지가 장식이 아니라 맥락과 행동을 전달하는가? |
| UX 정합성 | 선택·시작·보류·변경의 의미가 브랜드 보이스와 맞는가? |
| 상업 설득력 | 실제 판매 접점으로 발전시킬 기반이 있는가? |
| 개선 폭 | 단일 변경이 결과를 명확히 개선했는가? |
| 수정 부담 | 개선을 전파하는 데 필요한 수정량이 통제 가능한가? |

### 판정 기준

- 평균 8.0 이상: 최소 브랜드 입력이 실질적으로 작동함
- 평균 7.0–7.9: 작동하지만 원장 보강 필요
- 평균 6.9 이하: 브랜드 입력이 부족하거나 시스템 표현이 실패함
- 어떤 항목이든 4점 이하: 평균과 무관하게 원인 분석 후 재실험

## 9. 증거 기록

반드시 다음을 남긴다.

- Baseline과 개선본의 동일 크기 캡처
- 사용한 brand/product/campaign ID와 revision
- 각 변경 전후의 카피·에셋 diff
- 다섯 접점별 점수와 평가자 코멘트
- 누락·추정·권리 미확정 정보 목록
- 개선에 소요된 파일 수, 수정 단계 수, 회귀 결함 수

시각적 매력만으로 성공 판정하지 않는다. `브랜드 인식 → 의미 이해 → 행동 가능성 → 변경 전파`의 연쇄가 모두 확인되어야 한다.

## 10. 완료 조건

- 다섯 접점이 동일한 브랜드·제품·캠페인 데이터를 사용한다.
- 모든 미확정 제품·권리 정보가 명시적으로 표시된다.
- Baseline과 개선본의 변경 변수가 하나로 제한된다.
- 10개 평가 항목과 정성 코멘트가 모두 기록된다.
- 개선본의 평균이 Baseline보다 높거나, 상승하지 않은 원인이 설명된다.
- R3 산출물과 점수를 소급 수정하지 않는다.

이 브리프는 전체 브랜드 원장을 대체하지 않는다. 최소 단위 실험이 끝난 뒤 실제 시장·제품·권리 정보가 확보되면 `brand.common-surface.source-of-truth`의 새 revision으로 승격한다.
